# MangaMaker / AI漫画スタジオ

Delphi VCL製のWindows漫画ページ編集アプリです。登録した画像をコマへ配置し、吹き出しと文字を加え、作品単位で保存して連番PNGを出力します。現在はβ版で、仕様に沿う実装を進めるため保存形式の変更を許容します。全仕様の完成版ではありません。

仕様の基準は [`AIComicStudio_BBE698A4E88E81E3A882%81.md`](AIComicStudio_BBE698A4E88E81E3A882%2581.md)。現在の進捗・検証・再開手順は [note.md](note.md)、過去の作業記録は [使い方.txt](使い方.txt) を参照してください。

## ビルドと検証

Windows、ライセンス済みDelphi Win64コンパイラ、VCL、MSBuildが必要です。現行スクリプトはEmbarcadero Studio 37.0の標準インストール先と.NET Framework MSBuildを使用します。異なる環境では `build.ps1` のBDS/BDSCOMMONDIRとMSBuildパスを合わせてください。Delphi IDEの起動は不要です。

プロジェクトフォルダーからPowerShellで実行します。

```powershell
.\build.ps1 -SelfTest -OutputDirectory 'TestOutput\Verified'
```

Win64 Debugをビルドし、実行ファイルの場所、PASS/FAIL、自己検証フォルダーを表示します。`-Configuration Release` でReleaseを選べます。出力は `TestOutput` の下だけに許可し、直下の `MangaMaker.exe` へ配備しません。自己検証は新しい仮データフォルダーで非表示実行し、通常の作品/設定を使いません。

通常起動は生成された `TestOutput/Verified/MangaMaker.exe` を実行します。`-SelfTest` を省略するとビルドだけです。自己検証用の `--self-test` を手動で指定する場合も、出力先と `MANGAMAKER_DATA_ROOT` の隔離条件が必須です。

2026-10-13の最終候補はWin64 Debug/Releaseとも **1262項目PASS**、各構成のCLIガード2件もPASSです。保存再読込、途中取消、Undo/Redo、96/144 PPI、実ローカルパイプ、ネイティブの文字/出力ダイアログ開閉を含みます。証跡と実機で未確認の操作は [note.md](note.md) に記録しています。

実作品を使わず試す場合は、任意の専用フォルダーを指定して起動できます。環境変数は起動後に元へ戻します。

```powershell
$previousDataRoot = $env:MANGAMAKER_DATA_ROOT
try {
    $env:MANGAMAKER_DATA_ROOT = Join-Path $PWD 'TestOutput\TryData'
    Start-Process -FilePath '.\TestOutput\Verified\MangaMaker.exe'
} finally {
    $env:MANGAMAKER_DATA_ROOT = $previousDataRoot
}
```

## 制作の流れ

1. キャラ管理で人物名と参照画像を登録します。制作には有効なキャラ1件以上が必要です。
2. 新規作品でタイトルと話数を入力し、画像管理で場面画像を取り込みます。画像は作品フォルダーへコピーされます。
3. コマ割り管理でテンプレートを中央へドラッグして適用するか、コマ編集で作成します。
4. 画像配置のサムネイルをコマへドラッグします。画像のドラッグでパン、外周8点で比率を保って拡縮します。割当解除しても画像素材は保持します。
5. 吹き出しを対角2点で作成し、選択後に右の文字欄へ入力して「文字・設定を反映」。ダブルクリックで再入力できます。三角／思考しっぽは根元と先端の2点で追加し、しっぽ編集では根元・幅・先端の3点を操作します。
6. 保存し、PNG出力で変更ページだけ、または全ページを出力します。

上部/右側のアイコンはマウスを重ねると操作名を表示します。青は選択、減光は無効です。Tabで移動、Space/Enterで実行。画面/ツールの切替列は矢印キーも使えます。高さの狭い画面では右の設定欄をスクロールします。

| キー | 操作 |
| --- | --- |
| Ctrl+N / Ctrl+O / Ctrl+S | 新規 / 開く / 保存 |
| Ctrl+Z / Ctrl+Y | Undo / Redo |
| Ctrl+1～5 | コマ割り管理 / コマ編集 / 画像配置 / 吹き出し / 漫画効果 |
| Ctrl+Tab / Ctrl+Shift+Tab | 画面切替 |
| Esc | 作成途中・ドラッグ途中を取り消す（文字欄ではIME/編集欄に渡す） |
| Alt | 作成/頂点移動時のスナップを一時解除 |

## 専用文字入力

吹き出しを選択し、右の「専用文字入力」を押します。ダブルクリックは従来の右側文字欄へ移ります。ScreenDesignMakerから再利用したIME受取EditとUTF-16編集バッファを使用します。編集中は作品を変更せず、「確定」またはCtrl+Enterで1回のUndo操作として反映します。「取消」またはEscで元の文字を維持します。Tabでボタンへ移った場合もこれらのキーを使用できます。IME未確定中の矢印・Enter・EscはIMEへ渡し、文字全体の確定を防ぎます。

横入力では左右で文字間、上下で行を移動します。縦入力では上下で文字間、左右で列を移動します。Shiftで選択、Home/Endで表示行・列の先頭/末尾、Ctrl+Home/Endで全文の先頭/末尾へ移動します。Ctrl+矢印で単語移動、Ctrl+Backspace/Deleteで単語削除、Ctrl+A/C/X/V、Enter改行も使えます。入力内のCtrl+Z/Y（Ctrl+Shift+ZもRedo）は作品のUndoとは独立しています。長文はカーソルに追従してスクロールし、バーとホイールでも移動できます。

サロゲートペア、CRLF、結合濁点、異体字セレクタ、主な結合絵文字などをまとめて移動・削除します。Unicodeの全言語の書記素境界や複雑な双方向組版を完全に実装したものではありません。

右の縦書き設定を選んでから開くと縦入力になります。疑似カーソルは横組みで縦線、縦入力で横線です。入力と完成ページは同じGDI文字配置を使い、基本的な句読点・小書き仮名の位置、長音/括弧/英字の向き、2桁数字の縦中横、行頭/行末の基本禁則に対応します。入力画面と吹き出しでは領域・文字サイズが異なるため、最終的な改行位置はページ上で確認してください。フォントによる異体字/絵文字描画や高度な縦組みには追加検証が必要です。

IMEは入力受取中に有効とし、未確定文字も縦/横の入力領域へ表示します。候補位置は疑似カーソルに合わせ、確定結果は1つの文字列として受け取ります。終了/フォーカス離脱時には元の開閉・変換モードを復元します。非表示イベントと隔離したWindows IMEコンテキストの復元を検証済みですが、実IME候補の操作、実変換確定、他アプリへ戻った際の状態は実機で追加確認が必要です。既存の右側文字欄と「文字・設定を反映」も利用できます。

吹き出しごとにフォント名・サイズ・文字色、太字/斜体/下線/取消線を設定できます。装飾は全文字に適用します。使用履歴は入力の反映後に記録し、次にフォントリストを開いたときに先頭へ表示します。選択中のリスト順は保持します。

吹き出しは四角/角丸/楕円に対応し、塗り色・縁色・出力px基準の縁太さを持ちます。三角しっぽと3つの丸による思考しっぽを複数追加でき、本体と全しっぽ・文字は一緒に移動／拡縮します。縁太さは本体拡縮で維持します。しっぽの個別編集／削除はUndo対象です。「文字だけ表示」では完成PNGに本体と全しっぽを出さず、編集時にガイドを表示します。

文字は本体中央に配置します。吹き出しを選んで「文字配置」ツールに切り替えると、文字の内部ドラッグで位置を調整し、青8点で長文の折返しを保って文字全体を比率維持で拡縮できます。文字が本体からはみ出すことも許容します。文字の位置・サイズ変更、途中取消、Undo/Redoに対応し、本体を動かすと調整した文字も追従します。本文・縦横・フォント名・装飾を変更すると、本体の領域を基準に再配置します。

「設定・管理 → 画像生成プリセット」では共通指示を追加・編集・削除し、選択した指示を作品へ適用できます。作品にはその時点の名前・本文を保存するため、共通指示を後日変更しても作品の生成条件は維持されます。更新した共通指示を使う場合は明示的に再適用します。

キャラクター管理では、人物名と外見の共通補足をすべての服装へ共有し、服装・見た目の状態名と補足は別々に保存します。子を右クリックして「これを親にする」と、同じ人物の基本参照を切り替えます。共通人物IDと各参照ID・画像を保持し、旧親と他の服装は子として残します。親のドラッグは服装一式を移動し、子のドラッグは同じ人物の中だけで並べ替えます。

## Codexとのローカル連携

要求/応答の詳しい定義と例は [Tools/LocalBridge.md](Tools/LocalBridge.md) を参照してください。

通常起動すると、同じWindowsユーザー向けの名前付きパイプを開き、データ領域の `Runtime/bridge-プロセスID.json` に接続名を記録します。通常のデータ領域はドキュメントの `MangaMaker`、隔離起動では `MANGAMAKER_DATA_ROOT` です。複数起動時は対象プロセスのmanifestを明示してください。終了すると自身のmanifestを削除します。

```powershell
.\Tools\MangaMakerBridge.ps1 -ManifestPath '対象データ領域\Runtime\bridge-プロセスID.json'
```

初期要求は状態照会です。別の操作はUTF-8のJSONファイルを `-RequestFile` へ指定します。応答は `ok` と `data`、失敗時は `error` を返します。

| action | 主な指定 |
| --- | --- |
| `status` | 開いた作品ID、適用済み生成指示、管理画面の選択ID・編集中の名前/補足を照会 |
| `list_presets` | アプリ共通の生成指示を照会 |
| `list_assets` | `library` を `characters` または `images` に指定 |
| `read_asset` | `library` と `assetId`。子の場合は親と参照画像パスも取得 |
| `create_asset` | `library`、`name`、任意の `notes`・`parentId`。2階層まで |
| `register_image` | `library`、`assetId`、ローカル画像の絶対 `sourcePath`。任意の `expectedFileName` で既存画像の変更を検出 |

すべて `"version":1` が必須です。作品の画像を扱う要求では、状態照会で得た `projectId` も必須です。画像の `create_asset` は `mode` に `scene`（新規背景）、`child`（通常の子）、`alternate_scene`（別位置の背景）、`title`（タイトル用子）を指定でき、後者3つは `sourceId` で参照元を指定します。`child` では親の `parentId` でも指定できます。子に必要な人物・服装は `characterIds` 配列へ指定します。`read_asset` は選択した参照だけを返します。`requestId` は応答へ返します。再送の重複登録を防ぐIDではないため、通信結果が不明なときは対象を再照会してください。

```json
{"version":1,"action":"register_image","library":"images","projectId":"状態照会で得た作品ID","assetId":"登録する画像ID","sourcePath":"D:\\生成画像\\scene.png","expectedFileName":"照会で得たfile値"}
```

画像バイナリは送らず、生成ファイルを指定して登録します。登録先は選択状態から独立したIDで固定し、検証・保存に成功した画像を管理領域へコピーして採用します。旧画像を残すため、作品のUndo/Redoも使えます。画像管理を開いている間の登録や生成指示変更は、その管理操作のUndoへまとめます。正式な作品保存は通常の保存操作で行います。保存が成功した後のプレビュー失敗は `data.warnings` として返し、登録は成功のまま扱います。破損した参照画像も管理画面を閉じず再登録できます。

パイプはUTF-8のJSON＋改行、1接続1要求、要求1MiB／応答4MiB、接続後30秒の制限です。リモート接続を拒否し、作成ユーザーのSIDに限定したアクセス権を設定します。編集操作途中や別の入力画面を開いている間の登録は拒否します。この入口から自動でCodexへ生成指示を送る機能はなく、ユーザーからの生成指示に従って照会・登録します。

## コマ編集とページ管理

- 四角/楕円/角丸は対角2点クリック。多角形は頂点を順にクリックし、最初の点で閉じます。作成中の右クリックは最後の点を戻し、Escで中止します。
- スナップはページ基準の外枠（初期余白60px）、既存コマの角/辺、近隣コマの間隔を使用します。間隔は縦横の重なる隣の四角/楕円/角丸コマの外接範囲から測り、同じ隙間を作成や頂点編集へ再利用します。多角形の斜辺間隔は推定しません。近い候補を選び、同距離では従来の角/辺を優先します。外枠の外にも配置できます。
- 選択したコマの青い外周8点で縦横を独立して拡縮し、内部ドラッグで移動します。黄色い内側の点は頂点移動です。頂点の右クリックで削除、辺の右クリックで点を追加します。
- Ctrl+クリックで複数コマを追加/解除します。選択範囲の青8点で全体を縦横それぞれの比率で変形し、選択範囲内（コマ間の空白も含む）からドラッグして移動します。キャンバスにフォーカスがあるときCtrl+Aで全コマ、Deleteで選択コマと所属吹き出しを一括削除。移動/変形/削除はそれぞれ1回のUndoで戻せます。頂点編集は1コマを選択して行います。
- 四角の頂点を編集すると多角形へ変わります。楕円/角丸は固有形状を保持し、頂点追加/削除の対象外です。交差、重複、ゼロ面積、小さすぎる形は確定しません。最低3点、最大256点です。
- 4点分割は四角/凸多角形が対象です。外周上の2点で第1境界線を指定し、第3点で帯の幅、第4点で表示された対側交点を指定します。平行で等幅の帯へ補正し、水平/垂直/斜めに分割できます。帯幅は出力座標で最低4pxです。凹多角形/楕円/角丸は分割しません。
- 分割/頂点編集では画像のページ上位置を維持し、分割後は同じ画像UIDを使います。吹き出しの文字/位置も保持し、中心の属する結果コマ（帯上なら近いコマ）へ所属を更新します。
- コマ順序ツールは読む順番にクリックして番号を設定します。番号/選択点/ガイドは完成PNGへ出力しません。
- 現在のコマ割りを名前付き共通テンプレートとして登録できます。画像/吹き出しは登録せず、形状・配置・番号・ページ寸法を保存します。
- 共通テンプレートの一覧で登録項目を選び、「名前変更」「削除」で管理できます。組込項目は保持されます。削除しても、すでに適用したページのコマ割りは維持します。
- テンプレートを中央へ適用すると現在のコマ/吹き出しを置換します。Undoで一括復元できます。左のページ間へ落とすと新規ページへ挿入します。
- ページ一覧はCtrl/Shiftで複数選択でき、ドラッグ移動/一括削除をUndoできます。

「設定・管理 → ページ基準・共通プリセット」で全ページ共通の出力幅/高さ（100～8000px）と上下左右余白を変更できます。適用時は配置済みのコマ・画像・文字の座標を維持します。解像度変更は全ページのPNGを再描画し、外枠余白だけの変更では完成PNGを再利用します。外枠は配置制限ではなく、超過をステータスに表示します。

ページ基準は名前付きの共通プリセットへ登録・名前変更・削除できます。「登録」は共通ライブラリに保存し、「作品に適用」は作品の設定を変更します。作品には値のコピーを持つため、共通プリセットを後で変更/削除しても適用済み作品は変わりません。

## 保存データ

通常の保存先はWindowsのドキュメント配下 `MangaMaker` です。`MANGAMAKER_DATA_ROOT` を指定した起動ではそのフォルダーを使用します。

```text
MangaMaker/
├─ Characters/Library.json         共通キャラ/服装と参照画像
├─ Presets/Layouts.json            共通コマ割りテンプレート
├─ Presets/PageBases.json          共通ページ基準プリセット
├─ Presets/Generation.json         共通画像生成指示
├─ Presets/FontHistory.json        フォントの使用履歴
├─ Presets/RecentProjects.json     作品の読込履歴
├─ Effects/Library.json            共通効果素材とPNG
├─ Runtime/bridge-{PID}.json       起動中のローカルパイプ接続名
└─ Projects/{ProjectUID}/
   ├─ Project.json                正式保存
   ├─ Draft.json                  編集に伴う作業保存
   ├─ Pages/                      ページUID単位の保存
   ├─ Images/                     取り込んだ画像
   ├─ Effects/                    配置済み効果PNGの独立コピー
   └─ Output/                     0001.pngからの連番と内部キャッシュ
```

正式保存はCtrl+Sなどの明示操作です。開く際に新しい作業保存があれば復元を確認します。作品の移動/バックアップは画像を含む作品UIDフォルダー全体を対象にしてください。Undo履歴は実行中だけで、再起動後の履歴は保持しません。

ファイルメニューの「読込履歴」に、正常に開いた／保存した作品を最新20件まで記録します。作業データを復元しても通常のProject.jsonを履歴に残します。見つからない作品は履歴へ表示したまま無効化し、履歴のクリアは作品ファイルを削除しません。作品やDraftの読込失敗は編集中の作品を置換しません。

現行版は作品JSON version 1/2/3を読み込み、**保存はversion 3**です。version3は複数しっぽと文字/本体属性を保持します。旧形式の単一しっぽも読み込みます。旧実行ファイルはversion3非対応です。共通コマ割りライブラリは多角形のある場合version2です。β版では旧版互換維持や移行機能の追加を優先せず、現行データの保存・Undo整合と無効形状の拒否を優先します。

更新を試す前のバックアップ手順:

1. 編集を保存し、データが書き換わらない状態で現在のデータ保存先を確認します。通常はドキュメントの`MangaMaker`、環境変数を指定した起動ではその指定先です。
2. データ保存先全体を日付付きの別フォルダーへコピーします。`Projects/{ProjectUID}/`だけでなく、共有の **`Presets/Layouts.json`** と`Characters/`も含めます。元データとバックアップは上書きしません。
3. 試用には別のコピーを用意し、`MANGAMAKER_DATA_ROOT`をそのコピーへ向けます。そこで保存・読込を確認し、元作品や保管用バックアップを直接上書きしません。

差分PNGは内容・出力寸法・参照画像のハッシュで判定します。未変更ページはキャッシュを再利用し、並替/削除時は連番を整理します。参照画像を同じファイル名で更新した場合も該当ページを再描画します。失敗ページを正常出力済みと記録しません。

## 漫画効果

「漫画効果」（Ctrl+5）で素材・フィルター・枠装飾を切り替えます。集中線・スピード線・キラキラの組込透明素材をコマへドラッグすると、コマの範囲へ配置します。複数素材を置け、素材だけの移動・比率維持8点拡縮・削除・取消・Undo/Redoに対応します。素材は所属コマへ相対配置し、コマの移動・拡縮に追従します。分割時には全体の素材位置を保って両コマで切り抜きます。

フィルターはセピア・モノクロ・ぼかし・夢の色調と強度をコマへ反映します。フィルターには位置や8点編集はありません。枠は通常・二重・破線を選び、出力px基準の太さと色を設定できます。効果はコマの形状で切り抜き、吹き出しを後から重ねます。

設定メニューや効果一覧の「効果素材を管理」からPNGを共通登録し、名前変更・削除できます。配置時にPNGを作品の `Effects/` にコピーするため、共通側を変更・削除しても配置済み作品は維持されます。元PNGを削除せずUndo/Redoでも再利用します。通常の作品フォルダー全体のバックアップに配置済み素材も含まれます。共通ライブラリ全体をバックアップする場合はデータ領域の `Effects/` も含めてください。

## 開発中の制限

高度なフィルター、本体のギザギザ/波線/雲形の輪郭バリエーション、ルビや高度な文字組版には追加実装が必要です。間隔スナップは作成/頂点編集で利用し、コマ全体の移動・拡縮の自動整列は追加検討です。

文字入力の受取・編集バッファはScreenDesignMakerを参考に対象内で拡張し、入力/完成ページの共有文字配置、長文スクロール、入力内Undoを実装しています。縦入力の横線キャレットはユーザー要件に従った対象内実装です。ルビ、Unicode全言語の高度な組版は未実装です。詳細な引継ぎは [note.md](note.md) にあります。

極端に細い形状や非常に近い頂点では編集点が重なる場合があります。隔離負荷検証は80ページ（240×360px）と6ページ（1200×1700px・2400×3200px画像・ぼかし）の保存再読込/出力まで実施しました。実モニターでのDPI切替、実IME候補選択/変換の操作感、長時間制作は追加の実機確認が必要です。

`TestOutput/` と生成exe/DCU等は `.gitignore` の対象です。同期する成果物はソース、ビルド定義、仕様書、README、noteです。生成fixtureや実作品/個人データはリポジトリへ含めないでください。
